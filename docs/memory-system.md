# 长期记忆系统

agent100 在一次聊天正常结束时，从本次运行产生的用户与助手正文中提取长期记忆。工具调用、工具结果等序列化事件不会进入提取请求，临时记忆和无法在原对话中找到证据的候选记忆会被过滤。

## 保存流程

1. 模型从本次对话生成结构化候选记忆。
2. GLM Embedding-3 一次性将全部候选正文转换为 512 维向量。
3. 每条候选先按 `key` 全局查询旧记忆，再以余弦相似度全局查询相关记忆。
4. 决策模型根据候选与旧记忆选择 `add`、`confirm`、`replace` 或 `ignore`。
5. 服务层执行决策：新增记忆、增加确认次数、写入替代记忆并删除旧记忆，或者忽略候选。

每条正式记忆的 Qdrant point 包含正文向量和 payload。payload 保存 ID、正文、类型、稳定 key、scope、重要性、置信度、时效类型、证据、状态、时间及确认次数。向量只由 `content` 生成。

当前旧记忆语义查询使用 `0.5` 相似度阈值，最多返回 10 条；相同 `key` 的记忆通过精确查询参与决策。`scope` 作为记忆元数据保留，但不参与查重召回过滤。

## 查询流程

`search_memory` 是模型按需调用的只读工具。工具可接收最多 5 条查询，并按以下方式合并结果：

- 已知稳定 key 时，先按 `key` 全局精确查询最多 10 条。
- 将全部查询文本一次性向量化，每条查询全局返回最多 5 条相似度不低于 `0.6` 的记忆。
- 按记忆 ID 去重；同一记忆被多个查询命中时保留最高相似度。

## 配置与存储

向量化固定使用 GLM Embedding-3，因此必须在 `data/.env` 中配置 `ZAI_API_KEY`。聊天模型可以选择 GLM 或 DeepSeek，候选提取和记忆决策使用当前聊天模型。

Qdrant 以内嵌本地模式运行，默认数据库目录为 `data/memory/qdrant`。设置 `LLM_CLI_DATA_DIR` 后，记忆库会随其他运行数据迁移到指定目录。`data/` 已被 Git 忽略，不会进入源码包。

## 当前限制

保存流程按候选顺序执行，尚未提供事务回滚：如果中途请求失败，之前已经执行的记忆决策会保留。DeepSeek JSON Output 偶尔可能返回空正文，候选提取会最多尝试三次，并在重试请求中补充明确的 JSON 输出要求。
